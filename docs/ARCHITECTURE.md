# Architecture map for the HUB fork (DCSS stone_soup-0.34)

Agent-readable. Paths relative to `crawl-ref/source/` ("src/") unless noted. Line numbers verified in this checkout.
Repo root also has `crawl-ref/docs/` (upstream docs, do not touch); this file lives in root `docs/`.

## 1. Repo layout and build

- src/ C++ (flat, ~hundreds of `.cc/.h`). Object list: `src/Makefile.obj` (`OBJECTS = \` line 1; `tileweb.o` 330). New `hub/*.o` must be added there (or to `OBJECTS` in Makefile under an `ifdef HUB`).

## 2. Game loop
- Entry: `_launch_game_loop` main.cc:389 -> `_input()` called at 498; `_prep_input` 2510 (sets `you.turn_is_over=false`, `you.time_taken = player_speed()` at 2513).
- `_input()` main.cc:1079; gets command via `_get_next_cmd()` (decl 206, def 2745, call 1263); dispatches `process_command(cmd, prev_cmd)` main.cc:2094; calls `world_reacts()` at 1154/1167/1195/1329 when `you.turn_is_over`.
- `world_reacts()` main.cc:2596; `handle_monsters(true)` at 2648; `you.elapsed_time += you.time_taken` 2657.
- Monster energy: `handle_monsters` mon-act.cc:2755; `_monster_add_energy` mon-act.cc:1654 does `speed_increment += div_rand_round(mons.speed * you.time_taken, 10)` (1659); `handle_monster_move` 1928. Other uses of `time_taken`: mon-act.cc:1714, 1798, 1818; player.cc:631.
- Globals: `CLua clua`/`CLua dlua` main.cc:164-168; `crawl_environment env` main.cc:170 (decl env.h:137); `player you` main.cc:173 (decl player.h:143); `game_state crawl_state` state.cc (decl state.h:259; fields e.g. `test_list` 87, `tests_selected` 91).
- Per-level state in `env`: `env.grid`, `env.item` (a.k.a. mitm, size from `get_mitm_slot` items.cc:452), `env.shop` (env.h:77 `map<coord_def, shop_struct>`), `env.level_vaults`, `env.markers`.
- Realtime is infeasible: the loop is strictly turn-based and blocks on input. `getch_ck()` (libunix.cc:636, libw32c.cc:843) is called from ui.cc:3302 (`ui::pump_events`, non-USE_TILE_LOCAL branch 3295-3311; def 3167), prompt.cc:317, and menu loops (`ui::pump_events()` menu.cc:1593, 1652). Game state (monsters, `you`) only advances inside `world_reacts()`, which runs after a command returns; any menu (shop, inventory) runs a nested blocking UI loop inside `process_command`. Webtiles replaces the keyboard with `TilesFramework::await_input` (tileweb.cc:683) over a socket, still blocking. A kiosk menu must therefore be a modal blocking call, and external (Node) I/O must be synchronous or deferred to turn boundaries.

- Hub callers: `tiles.send_milestone` is called from hiscores.cc:3148, 3200, 3252 (inside `mark_milestone` 3156).
