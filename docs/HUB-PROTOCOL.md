# HUB-PROTOCOL v0

Canonical copy: `crawl-hub-crawl/docs/HUB-PROTOCOL.md`. Mirror: `crawl-hub/docs/HUB-PROTOCOL.md`.
Every message between the four parties is listed here before it is implemented.
Status column: `planned` (not built), `stub` (shape exists, no persistence), `done`.

Parties: **Browser** (TS client), **Node** (crawl-hub), **Py** (webtiles Tornado), **Game** (crawl C++).

## 1. Browser <-> Node (WebSocket `/ws`, JSON tagged on `t`)

Types live in `crawl-hub/shared/protocol.ts` and `shared/map.ts`. `PROTOCOL_VERSION` (currently 2) is sent in `hello` and `welcome`; a mismatch is answered with `error`.

Entity `tile` is a sprite name in the DCSS `player` sheet (e.g. `BASE_HUMAN`); map legend entries name sprites in the `floor`, `wall` and `feat` sheets. The client atlas is generated by `crawl-hub/scripts/import-tiles.mjs` from the fork's `webserver/game_data/static/tileinfo-*.js`.

| Message | Dir | Fields | When | Status |
|---|---|---|---|---|
| `hello` | B->N | `v`, `token?` | socket open; token resumes a session | done |
| `welcome` | N->B | `v`, `tick`, `tickHz`, `selfId` | reply to hello | done |
| `register` | B->N | `username`, `password` | sign up; 3-20 `[A-Za-z0-9]` (= webtiles nick_regex), pw 8-200 | done |
| `login` | B->N | `username`, `password` | sign in; 5 failures per 10 min then `rate_limited` | done |
| `auth_ok` | N->B | `accountId`, `username`, `token` | success; token lives 30 days | done |
| `auth_err` | N->B | `reason` | failure, rate-limited, session expired | done |
| `snapshot` | N->B | `tick`, `map` (MapData: id, legend, rows), `entities[]`, `selfId` | after join; one entity per account, later socket replaces earlier (`error "replaced"`) | done |
| `delta` | N->B | `tick`, `upsert[]`, `remove[]`, `ackSeq?` | each tick with changes, joined clients only; entities carry `dungeon?` while a classic game runs | done |
| `move` | B->N | `dir`, `seq` | key press; applied next tick | done |
| `chat` | B->N | `channel` local/global, `text` | send; 1-300 chars, 5 per 5 s; `/block name`, `/unblock name` | done |
| `chat` | N->B | `channel`, `from`, `text`, `tick` | fan-out; local = Chebyshev <= 8; blocked senders dropped | done |
| `profile_req` / `profile` | B<->N | `accountId` / `Profile` {username, createdAt, lastSeenAt, online, lastCharacter?, dungeon? {char, xl, place, watchUrl?}} | avatar click | done |
| `play` | B->N | `gameId` | Enter on the dungeon stairs; refused unless the entity stands on a `dungeon` door | done |
| `watch` | B->N | `username` | profile "Watch their game" | done |
| `crawl_open` | N->B | `mode` play/watch, `url` (`/crawl/#play-<gameId>` or `/crawl/#watch-<user>`), `token` | client stores the token as the `login` cookie and loads the URL in the embedded panel | done |
| `stash_list` / `stash` | B<->N | - / `items[]` {id, name, quantity, isRandart, depositedAt, depositedPlace} (never the blob) | town stash view | done |
| `offer_create` {stashItemId, toUsername, note?} / `offer_accept` / `offer_decline` / `offer_cancel` {offerId} / `offers_list` | B->N | | gifts of stash items; an offered item is held in escrow (not listable, not withdrawable) until resolved; no binding or fees | done |

| `rumors` | N->B | relic name, props summary, branch, age | tavern board | planned (Phase 2b) |
| `ping` / `pong` | B<->N | `now` / `now`, `serverNow` | RTT | done |
| `block` | B->N | `username`, `on` | same as `/block` command | done |
| `system` | N->B | `text` | server notices (rate limit, command results) | done |
| `error` | N->B | `reason` | any; `replaced`, `town full`, `protocol version mismatch` | done |

## 2. Node <-> Py (local HTTP + WebSocket bridge, loopback only)

Node also reverse-proxies webtiles under its own origin (`server/bridge/proxy.ts`): `/crawl/` -> webtiles `/`, and `/static/`, `/gamedata/`, `/socket` forwarded unchanged (the websocket is tunneled byte for byte). This is what lets the embedded webtiles client receive the hub-minted token as a same-origin cookie.

| Endpoint / message | Dir | Fields | Purpose | Status |
|---|---|---|---|---|
| `POST /hub/token` | N->Py | `{username}` -> `{username, token}` | mint a webtiles login cookie for the ws `token_login` message; creates the webtiles account on first use with a random password | done |
| `GET /hub/games` | N->Py | -> same JSON as `/status/lobby/` (name, game_id, char, xl, place, watch_url, ...) | Node polls every 2 s; entities gain `dungeon {char, xl, place}` and accounts record their last character | done |
| `POST /bridge/game` | Py->N | `{username, event}` -> `{reply}` | every `*hub_*` game message is relayed by `webtiles/hub/bridge.py` `_relay`; Node answers with the control message to send back, or null | done |
| (reply) | N->Py->Game | the `reply` object is sent to the game as a control message; on a failed POST the Python side synthesizes `*_fail {reason: "the hub is unreachable"}` for requests that expect an answer | done |

Auth between Node and Py: header `X-Hub-Secret` must equal webtiles `hub_bridge_secret` (Node env `WEBTILES_SECRET`); handlers refuse non-loopback clients and are not registered unless `hub_enabled = True`. Code: `webtiles/hub/bridge.py`, `crawl-hub/server/bridge/`.

## 3. Game <-> Py (existing crawl Unix socket; JSON; `*` prefix = server-only)

New server-only messages emitted by the game (all behind `HUB=y`):

| `msg` | Fields | When | Status |
|---|---|---|---|
| `*hub_kiosk_open` | `charName`, `xl`, `place`, `tagMajor`, `tagMinor` | `>` on a kiosk; the game blocks up to 2.5 s (`tiles.hub_wait_reply`) for `hub_stash_list` | done |
| `*hub_stash_deposit` | `blob` (base64 marshallItem), `tagMajor`, `tagMinor`, `name`, `basetype`, `subtype`, `quantity`, `isRandart`, `props?` (ARTP index -> value), `place`, `xl` | sent from the kiosk deposit menu; the item is removed only after `hub_stash_deposit_ok` | done |
| `*hub_stash_withdraw_req` | `stashItemId`, `charName` | player picks a stash item; Node marks it withdrawn atomically and answers `_ok`/`_fail` | done |
| `*hub_stash_withdraw_undo` | `stashItemId`, `reason` | game could not insert the item (pack full); Node restores it | done |
| `*hub_relic_lost` | one per randart: `blob`, `tag*`, `name`, `props`, `branch`, `depth`, `cause` | player death finalized | planned (2b) |
| `*hub_relic_query` | `branch`, `depth` | level generation in hub mode; game waits <= 200 ms | planned (2b) |
| `*hub_relic_placed` | `relicId`, `branch`, `depth` | relic placed by generator | planned (2b) |
| `*hub_item_event` | `kind` pickup/equip/drop/deposit, `name`, `props`, `place` | randart events for analytics | planned (2b) |
| `*hub_event` | free-form `{kind, ...}` | Phase 3 (race milestones, bughouse kills) | planned (3) |

Control messages Py sends to the game (handled in `tileweb.cc` `_handle_control_message`):

| `msg` | Fields | Purpose | Status |
|---|---|---|---|
| `hub_stash_list` | `items[]` {id, name, quantity, blob, tagMajor, tagMinor} | the game decodes blobs locally (skipping other tag versions) and shows them in a pickup-style menu | done |
| `hub_stash_withdraw_ok` / `hub_stash_withdraw_fail` | `stashItemId` / + `reason` | answer to the request; on ok the game inserts its decoded copy with `move_item_to_inv` | done |
| `hub_stash_deposit_ok` / `hub_stash_deposit_fail` | `stashItemId` / `reason` | the game removes the item only after `_ok` | done |
| `hub_stash_fail` | `reason` | generic failure (e.g. no hub account for this webtiles user) | done |
| `hub_relic_answer` | `relicId?`, `blob?`, `tag*` | generator places it or no-op | planned (2b) |
| `hub_spawn` | monster spec | bughouse (Phase 3) | planned (3) |

## 4. Rules

- Blobs are opaque to Node and Py; only the game reads them. Node stores `tagMajor`/`tagMinor` and
  refuses a withdrawal to a game reporting a different pair (the game sends its pair in `*hub_kiosk_open`).
- Hard exclusions enforced in the game at deposit (runes, the Orb, unrandarts) and re-checked by Node from
  `basetype`/`isUnrand` metadata.
- Every stash, offer and relic transition writes a ledger row in Node before the reply is sent.
- `*hub_relic_query` must never block level generation beyond its timeout; no answer means no relic.
- No game RNG is consumed by any hub call.
